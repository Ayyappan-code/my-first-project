WhatNext Vision Motors
Comprehensive Setup & Implementation Guide
Customer ordering, dealer assignment, stock control and automation on Salesforce

1. Project Overview
WhatNext Vision Motors wants a better customer ordering experience and less manual work. The Salesforce solution does three things:
Nearest dealer: an order is linked to the dealer that matches the customer's address.
Stock control: customers cannot order a vehicle that is out of stock.
Scheduled status update: a daily batch job changes Pending orders to Confirmed once stock is available.
Requirements and solutions
Requirement	Solution
Store vehicles, stock, dealers, customers	Six custom objects (Milestone 2)
Assign orders to nearest dealer	Record-triggered flow: Auto Assign Dealer
Block orders when out of stock	Apex trigger and handler class
Email reminders for test drives	Record-triggered flow with a scheduled path
Periodic stock check and status update	Batch Apex with Scheduled Apex

Skills covered: data modelling, fields and relationships, Lightning App Builder, record-triggered flows, Apex triggers, Batch Apex and Scheduled Apex.

7. Milestone 6: Flows
Flow 1: Auto Assign Dealer
Setup > Flows > New Flow > Triggered Automations > Record-Triggered Flow.
Object: Vehicle Order. Trigger: A record is created. Entry condition: Vehicle_Customer__c Is Null = False.
Get Records, label Get Customer Information: object Vehicle Customer; Id Equals the order's Vehicle_Customer__c; first record only.

Note: the match is exact text equality, not true distance. To store the dealer on the order itself, update the triggering order and set Dealer__c to {!Get_Nearest_Dealer.Id}.
Flow 2: Test Drive Reminder
New Flow > Record-Triggered Flow. Object: Vehicle Test Drive. Trigger: A record is created or updated. Entry condition: Status__c Equals Scheduled.

Step 1: Handler class - VehicleOrderTriggerHandler
public class VehicleOrderTriggerHandler {
  public static void handleTrigger(List<Vehicle_Order__c> newOrders,
      Map<Id, Vehicle_Order__c> oldOrders, Boolean isBefore,
      Boolean isAfter, Boolean isInsert, Boolean isUpdate) {
    if (isBefore && (isInsert || isUpdate)) preventOrderIfOutOfStock(newOrders);
    if (isAfter && (isInsert || isUpdate)) updateStockOnOrderPlacement(newOrders);
  }
 
  // Block orders when the vehicle is out of stock
  private static void preventOrderIfOutOfStock(List<Vehicle_Order__c> orders) {
    Set<Id> ids = new Set<Id>();
    for (Vehicle_Order__c o : orders) if (o.Vehicle__c != null) ids.add(o.Vehicle__c);
    if (ids.isEmpty()) return;
    Map<Id, Vehicle__c> m = new Map<Id, Vehicle__c>(
      [SELECT Id, Stock_Quantity__c FROM Vehicle__c WHERE Id IN :ids]);
    for (Vehicle_Order__c o : orders) {
      if (m.containsKey(o.Vehicle__c) && m.get(o.Vehicle__c).Stock_Quantity__c <= 0)
        o.addError('This vehicle is out of stock. Order cannot be placed.');
    }
  }
 
  // Reduce stock when an order is Confirmed
  private static void updateStockOnOrderPlacement(List<Vehicle_Order__c> orders) {
    Set<Id> ids = new Set<Id>();
    for (Vehicle_Order__c o : orders)
      if (o.Vehicle__c != null && o.Status__c == 'Confirmed') ids.add(o.Vehicle__c);
    if (ids.isEmpty()) return;
    Map<Id, Vehicle__c> m = new Map<Id, Vehicle__c>(
      [SELECT Id, Stock_Quantity__c FROM Vehicle__c WHERE Id IN :ids]);
    List<Vehicle__c> upd = new List<Vehicle__c>();
    for (Vehicle_Order__c o : orders) {
      if (m.containsKey(o.Vehicle__c)) {
        Vehicle__c v = m.get(o.Vehicle__c);
        if (v.Stock_Quantity__c > 0) { v.Stock_Quantity__c -= 1; upd.add(v); }
      }
    }
    if (!upd.isEmpty()) update upd;
  }
}
Step 2: Trigger - VehicleOrderTrigger (object Vehicle_Order__c)
trigger VehicleOrderTrigger on Vehicle_Order__c
    (before insert, before update, after insert, after update) {
  VehicleOrderTriggerHandler.handleTrigger(Trigger.new, Trigger.oldMap,
    Trigger.isBefore, Trigger.isAfter, Trigger.isInsert, Trigger.isUpdate);
}
Step 3: Batch class - VehicleOrderBatch
Finds Pending orders. When the vehicle has stock, it sets the order to Confirmed and reduces stock.
global class VehicleOrderBatch implements Database.Batchable<sObject> {
  global Database.QueryLocator start(Database.BatchableContext bc) {
    return Database.getQueryLocator([SELECT Id, Status__c, Vehicle__c
      FROM Vehicle_Order__c WHERE Status__c = 'Pending']);
  }
  global void execute(Database.BatchableContext bc, List<Vehicle_Order__c> orderList) {
    Set<Id> ids = new Set<Id>();
    for (Vehicle_Order__c o : orderList) if (o.Vehicle__c != null) ids.add(o.Vehicle__c);
    if (ids.isEmpty()) return;
    Map<Id, Vehicle__c> m = new Map<Id, Vehicle__c>(
      [SELECT Id, Stock_Quantity__c FROM Vehicle__c WHERE Id IN :ids]);
    List<Vehicle_Order__c> os = new List<Vehicle_Order__c>();
    Set<Id> changed = new Set<Id>();
    for (Vehicle_Order__c o : orderList) {
      if (m.containsKey(o.Vehicle__c)) {
        Vehicle__c v = m.get(o.Vehicle__c);
        if (v.Stock_Quantity__c > 0) {
          o.Status__c = 'Confirmed';
          v.Stock_Quantity__c -= 1;
          os.add(o); changed.add(v.Id);
        }
      }
    }
    List<Vehicle__c> vs = new List<Vehicle__c>();
    for (Id i : changed) vs.add(m.get(i));
    if (!vs.isEmpty()) update vs;
    if (!os.isEmpty()) update os;
  }
  global void finish(Database.BatchableContext bc) {
    System.debug('Vehicle order batch job completed.');
  }
}
Important: the trigger also reduces stock when an order becomes Confirmed, so stock can drop twice for one batch-confirmed order. If exact stock counts matter in your demo, remove the vehicle update from the batch.
Step 4: Scheduler class - VehicleOrderBatchScheduler
global class VehicleOrderBatchScheduler implements Schedulable {
  global void execute(SchedulableContext sc) {
    Database.executeBatch(new VehicleOrderBatch(), 50); // 50 = batch size
  }
}
Step 5: Schedule the job
Developer Console > Debug > Open Execute Anonymous Window. Paste the code and click Execute. Run it only once, because the same job name would be scheduled again. For midnight use '0 0 0 * * ?'.
String cronExp = '0 0 12 * * ?'; // runs daily at 12:00 PM
System.schedule('Daily Vehicle Order Processing', cronExp, new VehicleOrderBatchScheduler());

Verify: Setup > Quick Find > Scheduled Jobs. Daily Vehicle Order Processing should appear with type Scheduled Apex.

10. Troubleshooting
Flow object box stays red: click the object in the dropdown instead of typing it, or refresh and start a new flow. Check the object is Deployed.
"Provide at least one email recipient": put the customer Email in Recipient Addresses, not in Recipient ID.
A merge value is missing from the list: the lookup field is missing on the object. Create it and reopen the flow.
Apex "No such column": the field API name differs from the code (for example Stock_Quantity__c). Fix the field or the code.
Scheduled job missing: run the Execute Anonymous code again only if the job is not listed.
